# Phase 5 checkpoint — generalized AO + Qwen harness

Date: 2026-09-06
Status: TODO A and B complete; C in progress.

## Goal

Create one reusable AO + Qwen Code harness that is easy to apply to new repositories, supports multiple technology stacks, places global and project policy at the correct ownership layer, deduplicates rules, and keeps semantic review enabled by default but disableable per project.

## Confirmed baseline decisions

- GitHub + pull-request development is part of the baseline.
- Global Qwen rules may govern all Qwen sessions on the host.
- Every new repository receives baseline project templates.
- The harness must support different technology stacks.
- `bash scripts/verify` is the preferred stable deterministic verification interface.
- Semantic review defaults to enabled but projects may disable it.
- Do not mutate the working Premiumizearr/AO installation until generalized replacements are built and qualified.

## Source-of-truth ownership established

- `~/.qwen/QWEN.md`: universal Qwen engineering behavior.
- `~/.ao/rules/agentRules.md`: AO implementation/reviewer lifecycle.
- `~/.ao/rules/orchestratorRules.md`: AO coordination/routing lifecycle.
- `~/.ao/policies/semanticReviewPublication.md`: GitHub semantic-review publication.
- `~/.qwen/skills/ao-pr-review/references/contract.md`: technical review/result contract.
- `~/.qwen/skills/ao-pr-review/references/policy.md`: effort selection and semantic disposition.
- Project `PROJECT.md`: goals, scope, HITL and public/product contracts.
- Project `ARCHITECTURE.md`: architecture and approved technical decisions.
- Project `QWEN.md`: thin project entry point.
- Project `.qwen/review-rules.md`: project-only semantic review invariants.
- Proposed project `.qwen/review-config.json`: machine-readable review-risk additions.
- Project `scripts/verify`: executable mechanical verification authority.
- Project `.github/workflows/verify.yml`: CI wrapper around the same gate.
